ClawHost API — Before vs After

Backend refactoring: what changes, what stays

New API Routes
✅ NEW — Auth endpoints
POST /auth/register — email, password, name → JWT
POST /auth/login — email, password → JWT
POST /auth/refresh — refresh token → new JWT
GET /auth/oauth/:provider — redirect to GitHub/Google
GET /auth/oauth/:provider/callback — exchange code → JWT
GET /auth/me — current user profile
PUT /auth/me — update profile
PUT /auth/me/password — change password
🔄 RENAMED — Bot → Agent (same logic)
/bot/api/v1/bots → /api/v1/agents
/bot/api/v1/bots/:id/* → /api/v1/agents/:id/*
All sub-routes stay the same: /start, /stop, /restart, /status,
/channels, /skills, /devices, /config/models, etc.
🔄 CHANGED — Auth middleware
BearerAuth: validates api_token against apps table
JWTAuth: validates JWT, extracts user from token

BotOwnerAuth: checks bot.app_id == app.id
AgentOwnerAuth: checks agent.user_id == jwt_user.id

AdminAuth: validates admin_token from config
AdminAuth: checks jwt_user.role == "admin"
❌ REMOVED
/bot/api/v1/admin/apps/* — App CRUD (no more apps)
api.token, api.admin_token config — replaced by JWT + user roles
➕ NEW — Admin endpoints
GET /api/v1/admin/users — list all users
PUT /api/v1/admin/users/:id — update user (role, status)
GET /api/v1/admin/agents — list all agents (across users)
POST /api/v1/admin/agents/upgrade — upgrade all (kept from before)
POST /api/v1/admin/agents/:id/upgrade — upgrade specific
GET /api/v1/admin/stats — system overview (user count, agent count, running count)
