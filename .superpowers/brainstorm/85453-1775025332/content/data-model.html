ClawHost — Refactored Data Model

App removed, User added, Bot → Agent

Before (Current)
❌ App (tenant)
id, name, api_token, status
↓ has many
Bot
id, app_id, user_id (string), name,
slug, access_token, status, config,
endpoint, expires_at
Problems:
• App ↔ User is 1:1 in SaaS, redundant
• user_id is just a string, no real user
• "Bot" doesn't match product language
After (Refactored)
✅ User (new)
id, email, password_hash, name,
avatar, oauth_provider, oauth_id,
role (user/admin), status, api_token
↓ has many
✅ Agent (renamed from Bot)
id, user_id (FK → users), name,
slug, access_token, status, config,
endpoint, expires_at
Changes:
• App table deleted entirely
• User has real auth (password/OAuth)
• Agent.user_id is a real FK
• Admin via user.role, not separate token
Auth Flow
User Auth (JWT)
POST /auth/register → create user, return JWT
POST /auth/login → verify password, return JWT
GET /auth/oauth/:provider → OAuth redirect
GET /auth/oauth/:provider/callback → exchange token

All /api/v1/* routes: Authorization: Bearer <JWT>
Admin Auth
Same JWT, but middleware checks user.role == "admin"

No more separate admin_token config.
First user created can be auto-promoted to admin,
or via CLI command: ./clawhost admin promote <email>
